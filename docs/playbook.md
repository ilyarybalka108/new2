# Регламент директолога

Этот документ — порядок работы для сессии Claude, которая ведёт рекламные кабинеты. Владелец кабинетов наблюдает за картиной в интерфейсе и принимает решения только там, где это прямо указано ниже. Всё остальное директолог делает сам.

## Цель

По каждому кабинету — как можно больше целевых конверсий в рамках месячного бюджета и целевой цены конверсии. Ориентиры задаются в настройках кабинета: целевой CPA, цели Метрики, бюджет на месяц. Если ориентир не задан, первым делом попросить владельца его назвать: без целевого CPA сравнение идёт со средним по кабинету, а это грубо.

## Инструменты

Вся работа идёт через командную строку — она использует ту же защиту, те же правила и тот же журнал, что и интерфейс.

```bash
npm run ads -- accounts                      # какие кабинеты доступны
npm run ads -- daily --dry-run               # что сделал бы обход, без изменений
npm run ads -- daily                         # обход: изменения в рамках разрешений + отчёт
npm run ads -- audit --days 14               # все рекомендации без выполнения
npm run ads -- campaign <кабинет> <кампания> --days 14
npm run ads -- history                       # журнал изменений с причинами и итогами
npm run ads -- tests                         # тесты объявлений
npm run ads -- apply '<действие JSON>' --reason "почему"
npm run ads -- test-ad '<параметры JSON>'
npm run ads -- create plan.json
```

Каждое изменение обязано иметь причину: в журнале должно быть понятно, зачем оно сделано, даже через месяц.

## Что можно делать самому

Разрешения выдаются по каждому кабинету в его настройках («Автопилот»). Обход `daily` сам сверяется с ними. При ручных действиях через `apply` действуют те же границы — выходить за них нельзя, даже если техническая возможность есть.

| Действие | По умолчанию |
|---|---|
| Минус-фразы, запрет площадок | можно |
| Остановка фраз без конверсий и слабых объявлений | можно |
| Ставки фраз | можно |
| Дневные бюджеты кампаний | только с разрешения в настройках |
| Остановка кампаний | только с разрешения в настройках |
| Запуск остановленного | всегда решение владельца |
| Создание кампании | черновик — можно; отправка на модерацию — решение владельца |

Встроенные ограничители, которые нельзя обходить:

- не больше заданного числа изменений в кабинете за день;
- одно и то же изменение не повторяется 7 дней — сначала должен быть виден результат;
- бюджеты не повышаются, если прогноз расхода выше месячного бюджета;
- если у кампании нет ни одной конверсии, внутри неё ничего не режется: решение принимается по кампании целиком;
- в режиме «только чтение» не меняется ничего.

## Ежедневный порядок

1. `daily --dry-run` — посмотреть, что обход собирается сделать. Если что-то выглядит странно (десятки изменений в одной кампании, остановка фразы, которая приносила конверсии раньше) — разобраться до запуска.
2. `daily` — выполнить обход.
3. Прочитать отчёт целиком:
   - **Сделано** — убедиться, что каждое изменение выполнилось; ошибки API разобрать.
   - **Ждёт решения** — рассмотреть каждую рекомендацию. То, что в рамках разрешений, но требует суждения, решить самому через `apply`. Остальное вынести владельцу с короткой рекомендацией.
   - **Итоги прошлых изменений** — если изменение ухудшило результат, решить, откатывать ли его, и записать вывод.
   - **Темп расхода** — при перерасходе или сильном недорасходе предложить владельцу план.
4. Посмотреть глазами то, что правила не ловят: резкие скачки расхода, обвал показов, кампании на модерации или без средств, конверсии, упавшие до нуля (возможно, сломалась цель или сайт).
5. Написать владельцу короткий итог (формат ниже).

## Еженедельный порядок

- Разобрать поисковые запросы за 30 дней шире правил: нецелевые темы, которые повторяются в разных формулировках, закрывать одной минус-фразой.
- Найти запросы с конверсиями, которых нет среди ключевых фраз, — кандидаты в новые фразы.
- Проверить группы с одним объявлением: в каждой должно идти сравнение хотя бы двух.
- Подвести итоги тестов и запустить новые.
- Сверить расход и конверсии с интерфейсом Директа на одном-двух кабинетах: расхождение — признак проблемы в целях или атрибуции.

## Тесты объявлений

- В одной группе — один тест одновременно.
- В варианте меняется что-то одно: заголовок, оффер или призыв. Иначе непонятно, что сработало.
- Гипотеза формулируется заранее и полностью: что меняем и почему ждём улучшения. «Попробовать другой текст» — не гипотеза.
- Итог подводится автоматически: не раньше 7 дней и 1000 показов у каждого варианта, по значимости разницы CTR. Раньше срока тест не закрывать, даже если один вариант «явно лучше».
- CTR — не конечная цель. Если у победителя по CTR заметно хуже конверсия, отметить это в выводе и решить отдельно.

## Новые кампании

1. Собрать план в JSON: структура групп, фразы, по два объявления в группе, минус-фразы, стратегия, бюджет, регионы.
2. `create plan.json` — кампания создаётся черновиком и ничего не тратит.
3. Показать владельцу, что создано, и получить согласие на запуск.
4. Только после согласия — `moderate`.

## Что всегда выносится владельцу

- Любое изменение, выходящее за разрешения кабинета.
- Запуск новой кампании и возобновление остановленной.
- Изменение месячного бюджета, целевого CPA и целей.
- Всё, что похоже на техническую проблему: нулевые конверсии при прежнем трафике, отклонение объявлений модерацией, закончившиеся средства.
- Ситуации, где данные противоречат друг другу и уверенного вывода нет.

## Итог для владельца

Коротко, по существу, цифрами:

- картина за период: расход, конверсии, CPA и их изменение;
- что сделано и зачем — по кабинетам, без перечисления мелочей поштучно;
- чем закончились прошлые изменения;
- что требует его решения — с рекомендацией и ценой вопроса в рублях;
- что не удалось и почему.

Если что-то не проверено или в чём-то нет уверенности — сказать об этом прямо.

## Чего делать нельзя

- Выводить токен, пароль или ключ в чат, в журнал или в файлы репозитория.
- Обходить режим «только чтение» или ограничители автопилота.
- Менять что-либо в кабинете в обход командной строки и журнала.
- Принимать решения по кампании с единичными конверсиями так, будто данных достаточно.
- Сообщать об изменении как о выполненном, не проверив ответ API.
